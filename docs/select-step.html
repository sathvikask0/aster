The Select step

The peptide benchmark holds a whole assay out of training and asks the model to answer it anyway. It fails at chance across four configurations. Scaling the question axis from four to 484 lifts held-out transfer to 0.676 — but ablating the question text costs +0.006 ± 0.013, so that result is molecule propensity and not comprehension. Getting to a number I trust meant catching the evaluation misleading itself four separate times, the last of them my own. A shortcut and a discovery produce the same number. This page is the four cases and how each was caught.

The protocol

One model reads a peptide and a question in natural language — does this damage red blood cells? — and has to answer an assay held out of training entirely. Not a head per assay: a per-property head cannot answer a question it has no parameters for, so the ordinary supervised trainer refuses this dataset outright.

Questions and molecular identities are both held out. Splits are decided from identities and question assignments, never from label values. The protocol is written to disk before any optimization runs, checkpoints are hash-verified, and the encoder identity is recorded at training and re-read at evaluation so heads cannot be scored against a feature space they were never fitted on. The test split stays shut.

  • question — reads the peptide and the question. The hypothesis.
  • entity_only — never sees the question text. Detects a model coasting on the molecule alone.
  • question_only — never sees the peptide. Detects a model coasting on the label prior.
  • task_id — question as a lookup row, zero vector for anything unseen. Should be at chance on a held-out assay by construction.
Four controls on three seeds, twelve runs per configuration. They exist to make success falsifiable. If a control matches the model, the model has learned nothing the control hasn't — and that is the whole point of the exercise.

On peptides it fails, and the reason is arithmetic

At or below chance every time, with the control that ignores the peptide winning model selection every time. A protein language model did not help. The obvious next move is a bigger one.

These four checkpoints were selected under the objective that finding 03 breaks, so the digits above are not ones the current code would produce. Rescoring the saved validation predictions under the corrected rule does not rescue anything: rank skill comes out at −0.096 for question, −0.089 for entity_only and −0.055 for task_id — all three below chance — against exactly 0.0000 for question_only. Which restates the last column more precisely than it was first meant: the control wins not because it is good, but because it is the only one of the four that does not manage to be worse than chance.
34,000 peptide examples · 4 questions
The peptide axis has tens of thousands of training examples. The question axis has four — two per output head. Generalizing to a fifth assay means fitting a function of a 384-dimensional question embedding from two points. No encoder fixes that, so a 35M → 650M sweep would have spent days confirming a number the counting argument already predicted.

So the cheap discriminating experiment instead: the same protocol and the same four controls on 617 ToxCast assays — 1.53M labels over 8,579 molecules, split 484 / 68 / 65 by assay, no single-class assays, positive rates matched across splits. Small molecules rather than peptides, so this is a test of the mechanism and says nothing about peptide biology. If the mechanism is sound, plentiful questions should make it work.

Three ways the evaluation lied

01 Confound A 0.768 result that was almost entirely a shortcut
With molecules shared across splits, question reached 0.7679 on assays never seen in training. Against chance that reads as a finding. But entity_only, which never reads the question, reached 0.7635 — and the gap flipped sign between seeds. Nearly all of the headline was a molecule-level promiscuity prior: a compound active in 400 assays is a good bet in the 401st, no comprehension required. The only clean signal was calibration, where log loss separated 0.336 from 0.398, because assay names carry base rates and ToxCast base rates span 0.3%–83%.
02 Premature A stricter holdout was necessary, but did not license the claim
Rebuilt so that no molecule appears in two splits — 947k train labels, zero shared molecules. The shortcut shrank, and a gap appeared to open: 0.6693 ± 0.008 against 0.6489 ± 0.011, ahead on all three seeds (+0.021, +0.025, +0.015) where the loose split's +0.004 had flipped sign. Tightening the holdout was the right move and it did shrink the confound. But reading a result off this comparison was premature on two counts, and both are below: these checkpoints were chosen by a broken objective, and three seeds is not enough to know a sign.
03 Broken, then fixed The selection objective preferred a constant predictor
Checkpoints were selected on macro log loss. In the strict split question_only scored the best log loss of any control — 0.4228 against 0.4642 — while having AUROC = 0.5000 and MCC = 0. A literal constant. With base rates spanning 0.3%–83%, safe scores better than skilled, so selection would have shipped the constant and then scored it on test.

Fixed, in two stages, because the obvious fix was not enough. Dividing each assay's loss by its own base-rate reference gives a skill score, which does bound every constant predictor at ≤ 0. It was still the wrong thing to select on: question_only scored −0.2015 against question's −0.3809 and won again. Log loss is a proper scoring rule, so it answers calibration and discrimination at once, and these models are overconfident enough that calibration swamps the signal. On held-out questions that is not fixable — calibrating to an unseen assay's prior would need labels from that assay. So the two metrics were given separate jobs: AUROC selects, being invariant to monotone rescaling and pinning any constant at exactly 0.5000 (confirmed: question_only scores 0.5000 with zero variance across every seed), and skill reports, as the gate that must clear zero before an output is called a probability. Nothing clears it yet.
04 Mine The effect did not survive the fix, five more seeds, or real training
With selection corrected, everything was re-run. Every control's AUROC rose, because AUROC is now what selection optimises — but entity_only rose further than question, and the gap fell from +0.0204 to +0.0052. The broken objective had been penalising the control more than the model, and roughly three quarters of the headline was that artifact.

Then five more seeds, which is the part I should have run first. The three-seed ±0.0027 had been a low-variance cluster; across eight seeds the spread is five times larger and two seeds go negative. question reaches 0.6758 ± 0.0076 against 0.6700 ± 0.0076 — a difference of +0.0058 ± 0.0130, positive on 6 of 8 seeds, p = 0.25. Pairing by assay instead, which has far more power, lands on the same estimate and is no kinder: +0.0058 over 67 held-out assays, question ahead on 34 of 67 — a coin flip — p = 0.55, bootstrap 95% CI [−0.0125, +0.0246].

So the question channel contributes nothing measurable, and finding 02 was my own version of the same mistake as finding 01: a number that looked like a result because the comparison had not been made hard enough yet.

Two further checks, because "nothing measurable" is a weak claim to stop on. First, the assay questions are not a degenerate representation that an interaction term could never use: their MiniLM embeddings have an effective rank of 39.8 over 552 questions, so there is real structure in the text. Second, the runs above trained for only 1.7 passes over the data and peaked inside the first, which looked like it might explain everything — so they were retrained with twelve times the budget. It was not undertraining. Training loss halves, from 0.232 to 0.124, while held-out AUROC falls; the model overfits the training assays within one pass. And trained properly the comparison inverts: question lands −0.0055 below entity_only, so reading the question is worse than ignoring it.

The clinching number is the one against task_id, a control that gets a learned embedding per training assay and a zero vector for every unseen one, and so cannot transfer by construction. Its training curve tracks question's almost exactly (0.108 against 0.121 final training loss) and its held-out score is the same to within noise: −0.0005 ± 0.0063. An English description of an assay mechanism is worth what a blank vector is worth. The model is using the question as a lookup key, not as meaning — which is a sharper statement of the failure than the null was, and the one to design the next attempt against.

The test that isolates comprehension

Every comparison above ranks molecules within an assay, and that is the direction a molecule-level promiscuity prior owns: a compound active in 400 assays is a good bet in the 401st, so entity_only reaches 0.670 without reading a word. Transposing the comparison removes that prior by construction. Fix one molecule and rank the held-out assays for it: entity_only emits a single number for every assay, so all of them tie and its AUROC is exactly 0.5 — not empirically, structurally. Verified: 830 of 833 molecules get bit-identical predictions across every assay, the largest spread being 3×10−8, below float32 epsilon.

The confound transposes with the axis, though, which is the part worth stating plainly. In this direction the strong control becomes question_only: it predicts an assay's prevalence from its text, and a molecule really is likelier to be active in a high-prevalence assay. Beating it requires a genuine molecule-by-assay interaction, which is the thing in doubt.

Negative on 7 of 8 seeds, ahead on only 162 of 348 molecules, bootstrap 95% CI [−0.0325, −0.0069] — excluding zero on the wrong side. Adding the molecule makes assay ranking worse. Together the two rows say the model learned two marginals, how promiscuous a molecule is and how prevalent an assay is, and nothing joining them. In each direction the control that isolates the relevant marginal matches or beats the full model, so the second input is only dilution.

What survives, stated against its control. Held-out-assay transfer at 0.676 is real — large, reproducible, and far above the question_only floor of exactly 0.5000. What it is not is comprehension. Ablating the question text costs +0.0058 ± 0.0130, indistinguishable from zero, so the transfer is carried by molecule propensity: a compound active in many assays is a good bet in an unseen one, and the assay description is doing no measurable work on top of that. Reported against chance this would claim 0.676. Reported against its control it claims nothing yet.
One caveat on the framing, since it is easy to overread. “Four questions gave chance, 484 gave 0.676” is not a controlled comparison of question count: the two runs differ in dataset, molecule class, label volume and assay count all at once. What the peptide and ToxCast runs jointly support is narrower — that the question axis is where the peptide benchmark is starved, and that having 484 of them is still not sufficient for the question channel to carry signal here.

Where the questions came from, and what could not be fixed

Three assays ship structures with no sequence column, which leaves a protein encoder nothing to read. Sequences are recoverable from SMILES when the molecule really is a linear peptide of standard L-residues — so recover them, but make the parse prove itself: rebuild the recovered letters into a peptide and require its canonical SMILES to equal the input's. Anything else returns nothing, because feeding an encoder a molecule that does not exist is worse than feeding it nothing.

AssaySequences beforeRecoveredWhy

pampa0 / 6,8690 100% macrocyclic, 95% N-methylated — no sequence exists

Cross-checked against the 4,250 hemolysis rows that do publish a sequence: zero disagreements. The two macrocyclic assays correctly recover nothing, which matches upstream — it ships no sequence-based embeddings for exactly those three assays. A refusal was the honest answer, and those assays need a SMILES-native encoder instead.

A bug worth recording. Side chains were first keyed without marking the attachment point. Valine's isopropyl and proline's ring both reduce to propane that way, and leucine and isoleucine both reduce to 2-methylbutane. The parser read every proline as a valine and still looked like it worked — 100% "recovery" on toxicity. It was only visible against the 4,250 rows with published sequences, where it matched 245 of 400. Marking the alpha carbon as a dummy atom separates all twenty residues. Recovery then honestly drops to 42%.

What this changes

Four evaluation failures, and the honest tally is that three of them were inflating a number and the fourth was me believing the inflated number. What is left standing is a real transfer result with no demonstrated question-comprehension component, an encoder that was never the bottleneck, and a selection rule that now cannot be won by giving up. The test split has still never been opened: test_evaluated: false on every run above.

  • Three seeds is not a result. The cheapest of these four lessons and the one I paid for twice. Eight seeds cost six minutes and reversed the conclusion; the seed spread was five times what three seeds implied.
  • Pair the comparison on the axis with the most units. Eight seeds give eight observations; 67 held-out assays give 67, and the per-assay pairing is what showed the effect was a coin flip rather than merely noisy.
  • Selection and reporting need different metrics. Discrimination selects, because it survives miscalibration; calibration gates, because it is what makes an output a probability. A single proper scoring rule tries to do both and does neither on held-out questions.
  • Get more peptide questions. Nine assays is thin and four are consumed by the splits. Still the change that attacks the real bottleneck — and now the one with a clean null to beat.
  • Match the holdout to the claim. Holding molecules out changed the answer once already. If the claim is a new scaffold, hold out scaffolds.
A sanity anchor for the new metric. Per-task supervised heads, which do see their own assay in training, score +0.202 calibration skill across nine peptide assays — positive on eight of nine. A constant predictor scores exactly 0.0000 rank skill and −0.009 calibration skill. The held-out-question models score −0.47 and worse. So the negative skill is caused by the held-out-ness, not by a broken metric or a broken model: calibration is reachable once you have seen the assay, and not before.

Every run above is reproducible from the repository: pinned dataset revisions with checksums, the protocol written before optimization, and test_evaluated: false on all of them. 196 tests, green in CI.
