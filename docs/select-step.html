The Select step

The peptide benchmark holds a whole assay out of training and asks the model to answer it anyway. It fails at chance across four configurations. Scaling the question axis from four to 484 fixes it — but getting there meant catching the evaluation misleading itself three separate times. A shortcut and a discovery produce the same number. This page is the three cases and how each was caught.

The protocol

One model reads a peptide and a question in natural language — does this damage red blood cells? — and has to answer an assay held out of training entirely. Not a head per assay: a per-property head cannot answer a question it has no parameters for, so the ordinary supervised trainer refuses this dataset outright.

Questions and molecular identities are both held out. Splits are decided from identities and question assignments, never from label values. The protocol is written to disk before any optimization runs, checkpoints are hash-verified, and the encoder identity is recorded at training and re-read at evaluation so heads cannot be scored against a feature space they were never fitted on. The test split stays shut.

  • question — reads the peptide and the question. The hypothesis.
  • entity_only — never sees the question text. Detects a model coasting on the molecule alone.
  • question_only — never sees the peptide. Detects a model coasting on the label prior.
  • task_id — question as a lookup row, zero vector for anything unseen. Should be at chance on a held-out assay by construction.
Four controls on three seeds, twelve runs per configuration. They exist to make success falsifiable. If a control matches the model, the model has learned nothing the control hasn't — and that is the whole point of the exercise.

On peptides it fails, and the reason is arithmetic

Eight assays, then nine after wiring up the nonfouling split upstream had always shipped. Morgan fingerprints, then frozen ESM-2 concatenated on top. Held-out hemolysis AUROC:

At or below chance every time, with the control that ignores the peptide winning model selection every time. A protein language model did not help. The obvious next move is a bigger one.

34,000 peptide examples · 4 questions
The peptide axis has tens of thousands of training examples. The question axis has four — two per output head. Generalizing to a fifth assay means fitting a function of a 384-dimensional question embedding from two points. No encoder fixes that, so a 35M → 650M sweep would have spent days confirming a number the counting argument already predicted.

So the cheap discriminating experiment instead: the same protocol and the same four controls on 617 ToxCast assays — 1.53M labels over 8,579 molecules, split 484 / 68 / 65 by assay, no single-class assays, positive rates matched across splits. Small molecules rather than peptides, so this is a test of the mechanism and says nothing about peptide biology. If the mechanism is sound, plentiful questions should make it work.

Three ways the evaluation lied

01 Confound A 0.768 result that was almost entirely a shortcut
With molecules shared across splits, question reached 0.7679 on assays never seen in training. Against chance that reads as a finding. But entity_only, which never reads the question, reached 0.7635 — and the gap flipped sign between seeds. Nearly all of the headline was a molecule-level promiscuity prior: a compound active in 400 assays is a good bet in the 401st, no comprehension required. The only clean signal was calibration, where log loss separated 0.336 from 0.398, because assay names carry base rates and ToxCast base rates span 0.3%–83%.
02 Decisive A stricter holdout is what made the real effect visible
Rebuilt so that no molecule appears in two splits — 947k train labels, zero shared molecules. The shortcut shrank and the effect separated: 0.6693 ± 0.008 against 0.6489 ± 0.011, ahead on every seed (+0.021, +0.025, +0.015) where the loose split's +0.004 had flipped sign. Same data, same model, same code. Tightening the holdout turned an unreadable comparison into a sign-stable one — the looser split had been hiding the result, not inflating it.
03 Broken metric The selection objective preferred a constant predictor
Checkpoints were selected on macro log loss. In the strict split question_only scored the best log loss of any control — 0.4228 against 0.4642 — while having AUROC = 0.5000 and MCC = 0. A literal constant. With base rates spanning 0.3%–83%, safe scores better than skilled, so selection would have shipped the constant and then scored it on test. Found before the test split was opened; it stays shut until the selection rule is fixed.
The transferable lesson is the reporting baseline. Molecule propensity survives molecule holdout, so question transfer has to be stated against entity_only, not against chance. Reported against chance, this work would claim 0.669. Reported honestly, it claims +0.020 over a control that reads no question at all.

Where the questions came from, and what could not be fixed

Three assays ship structures with no sequence column, which leaves a protein encoder nothing to read. Sequences are recoverable from SMILES when the molecule really is a linear peptide of standard L-residues — so recover them, but make the parse prove itself: rebuild the recovered letters into a peptide and require its canonical SMILES to equal the input's. Anything else returns nothing, because feeding an encoder a molecule that does not exist is worse than feeding it nothing.

AssaySequences beforeRecoveredWhy
toxicity0 / 11,0364,637 (42%) Plain linear L-peptides; verified by reconstruction
caco20 / 6060 100% macrocyclic, 85% N-methylated — no sequence exists
pampa0 / 6,8690 100% macrocyclic, 95% N-methylated — no sequence exists

Cross-checked against the 4,250 hemolysis rows that do publish a sequence: zero disagreements. The two macrocyclic assays correctly recover nothing, which matches upstream — it ships no sequence-based embeddings for exactly those three assays. A refusal was the honest answer, and those assays need a SMILES-native encoder instead.

A bug worth recording. Side chains were first keyed without marking the attachment point. Valine's isopropyl and proline's ring both reduce to propane that way, and leucine and isoleucine both reduce to 2-methylbutane. The parser read every proline as a valine and still looked like it worked — 100% "recovery" on toxicity. It was only visible against the 4,250 rows with published sequences, where it matched 245 of 400. Marking the alpha carbon as a dummy atom separates all twenty residues. Recovery then honestly drops to 42%.

What this changes

The mechanism is sound and the bottleneck is the number of questions, not the encoder. Four questions put held-out-question transfer at chance; 484 put it at 0.669 on assays and molecules never seen. Nothing about a bigger protein model would have changed that, and two runs settled what a model-size sweep would have obscured.

  • Fix the selection rule first. Skill scores against per-assay base rates, so calibration and discrimination are separated before a checkpoint is chosen. No test evaluation until then.
  • Report against controls, not chance. Every future number on this site carries its entity_only reference beside it.
  • Get more peptide questions. Nine assays is thin, and four of them are consumed by the held-out splits. This is the only change that attacks the real bottleneck.
  • Match the holdout to the claim. Holding molecules out changed the answer once already. If the claim is a new scaffold, hold out scaffolds.

Every run above is reproducible from the repository: pinned dataset revisions with checksums, the protocol written before optimization, and test_evaluated: false on all of them. 165 tests, green in CI.
