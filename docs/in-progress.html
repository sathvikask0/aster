The model comparison has been executed (reports/amp_v03_random.json, amp_v03_random_balanced.json, amp_v03_matched_balanced.json) but those runs are not results: they predate the 28 September answer-label correction, so every model that reads answer text was trained against inverted option indices. The question this experiment exists to answer

v0.2 established two things that point in opposite directions. The text encoder stopped being a lookup table (+0.054 over task_id). And against the shortcut ceiling, the honest zero, the mean lift was −0.058, with 4 of 5 held-out targets below a 20-dimensional bag of amino acids.

Both can be true because the benchmark lets a model score well for a reason that has nothing to do with the question. Positives for a target are real antimicrobial peptides; negatives are peptides with no record for that target, drawn at random. Those two pools differ in bulk composition — cationic, more hydrophobic — so "is this peptide cationic and amphipathic?" answers most of the benchmark without reading the prompt. On C. albicans a composition probe reaches 0.721 that way.

So the number that decides whether Aster's premise is real — does encoding the question as language buy anything? — is measured against a ceiling high enough to swallow the entire effect. The fix is not a better model. It is a benchmark where the shortcut does not exist.

Design

1. Composition-matched negatives. Each positive claims its nearest unused negative candidate in 21-dimensional space (20 amino-acid frequencies plus scaled length), greedily, hardest positives first, with a caliper of 0.35 — a positive with no candidate inside the caliper is dropped rather than paired with a distant one. Negatives are additionally drawn only from peptides with records against ≥3 other pathogens (negative_policy="matched"), so absence of a record is less likely to mean "never assayed".

The two classes then have near-identical composition, and a composition probe is at chance by construction — not as an empirical hope.

2. Mechanism-swap ablation. At test time, give each held-out target the wrong mechanism prompt: the fungal chitin/ergosterol prompt for a Gram-negative target, the LPS prompt for the fungal one. If accuracy is unchanged, the prompt is functioning as a task identifier that happens to be spelled in English, and the mechanism language is decoration.

Implemented 28 September 2026 in aster/real/ablation.py, and it now runs inside both AMP runners. Donor prompts are drawn from the training tasks, so the swapped text is something the model has seen and a drop cannot be explained away as out-of-distribution input. The reading is committed in code (read_swap) rather than written after the numbers arrive. One caveat is stated there and worth repeating: a drop shows the model is sensitive to prompt content, which is weaker than showing it uses the mechanism correctly — a model keyed to surface features that correlate with the family would drop too. Necessary, not sufficient. entity_only and task_id are excluded because neither reads the question.

3. Same five models, same held-out targets, same reading rule. cross_attention, dual_dot, task_id, question_only, entity_only; lift reported against the ceiling with binomial intervals; task_id shown only as the lookup floor, never as the zero.

The fourth row is a live possibility and is the reason this is worth running: after matching, the remaining signal must come from residue order, which is exactly what ESM-2 is supposed to provide and a composition vector cannot.

Unfreezing the protein encoder

Every AMP number so far, including the void v0.3 runs, trained over cached ESM-2 vectors: the encoder ran once, offline, and never learned anything about peptides. scripts/run_amp_finetune.py puts it back in the graph with its last blocks trainable, on the matched-negative data where the composition shortcut is at chance by construction — so whatever a fine-tune buys has to come from residue order.

Three things keep that from becoming an unreadable number. The heads are the same classes used unchanged, so *_live against *_frozen differs in exactly one factor. entity_only gets trainable blocks too: it is the control for “answers without reading the question” and it has a protein encoder, so unfreezing only the hypothesis model would hand it capacity the control was denied and call the difference transfer. And encoder_drift is reported beside every accuracy, because a gain with drift near zero is a head effect wearing a fine-tuning label.

The text tower stays frozen. Unfreezing it as well is a separate experiment; mixing it in would leave neither attributable. Not yet run.

One seed is not a result

The second pre-registered outcome — “lift is positive but inside the intervals” — needs seed variance to resolve, and no run here has had it. scripts/compare_amp_runs.py reads several reports and prints the spread across seeds, whether the lift is positive in every run, and whether it exceeds that spread. A lift smaller than the seed spread is not a finding about the model. It also refuses to average incomparable runs: a report without label_semantics_version predates the answer-label fix, and the three stored v0.3 files are rejected by name for exactly that reason (there is a test that asserts it).

What would still be wrong afterwards

Matching removes a confound; it does not create measured negatives. Every label in this benchmark is still presence-or-absence in a literature table. A clean answer needs assay data with recorded inactives — an MIC table with upper bounds, not a list of hits.
