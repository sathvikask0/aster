v0.3 resolved: the shortcut is gone, and so is the signal

Aster v0.3 · design frozen 27 September 2026 · run executed 28 September 2026

The fourth pre-registered outcome is the one that landed. “Everything collapses to chance. The benchmark's signal was the shortcut. The dataset cannot test the premise and a different data source is required.” Written before the run; recorded here unedited.

A separate positive control, added after the null, shows the fine-tuning machinery is sound. The matched benchmark is unlearnable; the code that ran on it is not broken.

Status: complete. The comparison was re-run under label semantics v2 and resolved to the fourth pre-registered outcome. Three earlier files (reports/amp_v03_random.json, amp_v03_random_balanced.json, amp_v03_matched_balanced.json) predate the 28 September answer-label correction — every model that reads answer text was trained against inverted option indices — so they are kept as history and are not results. The numbers on this page come from reports/ft_35m_minilm_frozen_s42.json, scrambled_8m_s42.json and scr_35m_s42..44.json.

The question this experiment exists to answer

v0.2 established two things that point in opposite directions. The text encoder stopped being a lookup table (+0.054 over task_id). And against the shortcut ceiling, the honest zero, the mean lift was −0.058, with 4 of 5 held-out targets below a 20-dimensional bag of amino acids.

Both can be true because the benchmark lets a model score well for a reason that has nothing to do with the question. Positives for a target are real antimicrobial peptides; negatives are peptides with no record for that target, drawn at random. Those two pools differ in bulk composition — cationic, more hydrophobic — so "is this peptide cationic and amphipathic?" answers most of the benchmark without reading the prompt. On C. albicans a composition probe reaches 0.721 that way.

So the number that decides whether Aster's premise is real — does encoding the question as language buy anything? — is measured against a ceiling high enough to swallow the entire effect. The fix is not a better model. It is a benchmark where the shortcut does not exist.

Design

1. Composition-matched negatives. Each positive claims its nearest unused negative candidate in 21-dimensional space (20 amino-acid frequencies plus scaled length), greedily, hardest positives first, with a caliper of 0.35 — a positive with no candidate inside the caliper is dropped rather than paired with a distant one. Negatives are additionally drawn only from peptides with records against ≥3 other pathogens (negative_policy="matched"), so absence of a record is less likely to mean "never assayed".

The two classes then have near-identical composition, and a composition probe is at chance by construction — not as an empirical hope.

2. Mechanism-swap ablation. At test time, give each held-out target the wrong mechanism prompt: the fungal chitin/ergosterol prompt for a Gram-negative target, the LPS prompt for the fungal one. If accuracy is unchanged, the prompt is functioning as a task identifier that happens to be spelled in English, and the mechanism language is decoration.

Implemented 28 September 2026 in aster/real/ablation.py, and it now runs inside both AMP runners. Donor prompts are drawn from the training tasks, so the swapped text is something the model has seen and a drop cannot be explained away as out-of-distribution input. The reading is committed in code (read_swap) rather than written after the numbers arrive. One caveat is stated there and worth repeating: a drop shows the model is sensitive to prompt content, which is weaker than showing it uses the mechanism correctly — a model keyed to surface features that correlate with the family would drop too. Necessary, not sufficient. entity_only and task_id are excluded because neither reads the question.

3. Same five models, same held-out targets, same reading rule. cross_attention, dual_dot, task_id, question_only, entity_only; lift reported against the ceiling with binomial intervals; task_id shown only as the lookup floor, never as the zero.

Unfreezing the protein encoder

Every AMP number so far, including the void v0.3 runs, trained over cached ESM-2 vectors: the encoder ran once, offline, and never learned anything about peptides. scripts/run_amp_finetune.py puts it back in the graph with its last blocks trainable, on the matched-negative data where the composition shortcut is at chance by construction — so whatever a fine-tune buys has to come from residue order.

Three things keep that from becoming an unreadable number. The heads are the same classes used unchanged, so *_live against *_frozen differs in exactly one factor. entity_only gets trainable blocks too: it is the control for “answers without reading the question” and it has a protein encoder, so unfreezing only the hypothesis model would hand it capacity the control was denied and call the difference transfer. And encoder_drift is reported beside every accuracy, because a gain with drift near zero is a head effect wearing a fine-tuning label.

The text tower can now be unfrozen too, behind --unfreeze-text, and it is a separate flag rather than a default so the runs read as a ladder: frozen, protein-live, both-live. If both towers move at once and the number rises, nothing says which one did it, so the comparison script warns when the two kinds of run are mixed.

Turning it on adds question_only to the live set, which is the point rather than a side effect. question_only is the control for “answers from the prompt alone”; handing the hypothesis model trainable text blocks while denying them to that control would inflate the hypothesis by exactly the capacity withheld — the same argument that gives entity_only a live protein encoder. If question_only gains as much, the text tower learned the label prior rather than the question. Drift is reported per tower, so a run where only one actually moved is visible instead of assumed.

The cost is smaller than it looks: there is one question per task and two answer strings in the entire benchmark, so a step forwards about 23 short sequences rather than one per row. With the text tower live the batch carries question and answer indices instead of cached vectors — a cached vector cannot carry a gradient — and the mechanism swap moves the index. The protein-only run has now been executed — on matched negatives (a null, above) and on scrambled decoys (a pass, above). The both-towers run has not.

One seed is not a result

The second pre-registered outcome — “lift is positive but inside the intervals” — needs seed variance to resolve, and no run here has had it. scripts/compare_amp_runs.py reads several reports and prints the spread across seeds, whether the lift is positive in every run, and whether it exceeds that spread. A lift smaller than the seed spread is not a finding about the model. It also refuses to average incomparable runs: a report without label_semantics_version predates the answer-label fix, and the three stored v0.3 files are rejected by name for exactly that reason (there is a test that asserts it).

What the matched run returned

ESM-2 650M, last two blocks unfrozen, 2,000 peptides, matched negatives. Accuracy 0.514 against a 0.515 ceiling. Validation loss sat at 0.6931 — ln 2, the value of a constant prediction — for every epoch until early stopping, and encoder_drift came in at 7.8e-05: 39.4M trainable parameters that effectively did not move. The mechanism swap cost 0.003, inside the intervals, so the prompt was again a task identifier spelled in English.

The 35M frozen ladder agrees. Every arm lands inside the ceiling band, and entity_only_live at 0.538 matches dual_live at 0.545 — the control that never reads the question does as well as the model that does.

Why it is unlearnable, measured rather than argued

The cause is in the construction. On the shipped data under matched with balanced tasks, seed 42:

Negatives with confirmed activity against ≥3 other pathogens100%
Mean confirmed pathogen activities, negatives5.3
Mean confirmed pathogen activities, positives7.3

covered and matched require min_coverage records, so every presumed negative is a confirmed broad-spectrum antimicrobial peptide. Composition matching then strips length and residue frequency. What remains is the same sequence presented with opposite labels, distinguished only by a prompt the swap ablation has already shown to be a bare task id. The ceiling near 0.51 is not a weak result to be improved on; it is the real ceiling.

This is the honest reading of the design, and it is worth stating plainly: the two policies built to remove a confound removed the signal with it. Matching on composition is matching on the discriminator, because in this data the classes differ in little else.

The control that separates a bad task from bad code

A null cannot distinguish “the task cannot be learned” from “the code cannot learn”, and that distinction decides whether more compute is worth buying. --negative-policy scrambled supplies the missing rung: negatives are order-shuffled copies of the positives — identical composition, identical length, destroyed motif and helicity. A shuffle that reproduces its source, collides with another decoy, or matches any real peptide in the library is rejected, so a decoy is never silently a true positive. Both ceilings are 0.5 by construction and any lift is residue order, which is what ESM-2 is supposed to supply.

What this control does not show

Three limits, stated because the 0.86 is easy to misread.

It says nothing about the prompts. With scrambled decoys the correct answer does not depend on the pathogen, so entity_only ≈ dual is the expected outcome, not a finding. The mechanistic-prompt hypothesis is untested by this run.

Quote the gap, not the accuracy. The live−frozen comparison is within-seed and stable. Raw accuracies are not comparable across seeds: seed 44 draws a different held-out mix and its ceiling rises to 0.621.

Real AMPs against their own shuffles is an easier question than real biology. It establishes that the encoder path learns residue order. It does not establish that it learns antimicrobial activity as a clinician would define it.

What would still be wrong afterwards

Matching removes a confound; it does not create measured negatives. Every label in this benchmark is still presence-or-absence in a literature table. A clean answer needs assay data with recorded inactives — an MIC table with upper bounds, not a list of hits.

That sentence was written before the run and it is now the whole critical path. The fourth outcome landing means the blocker is data, not model capacity: scaling to a larger ESM on the matched benchmark reproduces a null at higher cost, because the ceiling is a property of the labels. The next experiment worth running is the one that acquires negatives somebody actually measured.
